# ADR-008 协作入口层迁移飞书与群聊旁听上下文

> 状态：讨论稿（待确认）
> 日期：2026-09-24
> 前置依赖：ADR-001 协作入口层、ADR-002 三层记忆、ADR-003 ConsoleAgent
> 关联：ADR-005 技能层（本文修订其通道前提）

## 背景

协作入口层原采用钉钉 Stream 模式（见 ADR-001）。使用中发现两个能力边界，均来自钉钉
平台而非代码实现：

1. **群聊旁听不可行**。钉钉企业内部机器人只推送「@机器人」的消息（官方《接收消息》文档：
   推送触发条件仅为「用户@群机器人或与机器人单聊」），群友之间的自然讨论对机器人不可见。
2. **历史消息不可回拉**。钉钉不向普通企业内部机器人提供群历史消息 API，机器人错过即永久缺失。

这两点导致 ADR-003 消息管线中的「群聊上下文」段落名不符实：`session.messages` 实际只含
@ 问答往来，群内讨论结论只有被成员手动转述才能进入系统记忆。

迁移动因：项目为个人项目，协作群可无痛整体迁移。评估飞书后确认其平台能力恰好补齐两个
边界（见「飞书平台能力依据」），故决策：**飞书为唯一协作入口通道，移除钉钉通道**。

## 飞书平台能力依据

飞书开放平台对本文两项核心能力（全量群消息接收、历史消息回拉）均有官方 API 支持，这是
迁移决策的平台层事实基础。依赖 `lark-oapi`（Python SDK，WebSocket 长连接）做事件订阅与
API 调用；个人版飞书自建应用，企业管理员即创建者本人，权限申请无外部审批依赖。

### 全量群消息接收

订阅 `im.message.receive_v1` 事件并申请 `im:message.group_msg` 权限后，机器人所在群的
全部用户消息均会推送（无需 @）。权限变体：`im:message.group_msg`（仅用户消息）与
`im:message.group_msg.include_bot:read`（含其他机器人消息，不含自身）。事件订阅支持
长连接模式（官方 SDK `lark.ws.Client`，Python），与钉钉 Stream 模式接入形态同构。
官方提示推送可能重复，幂等去重应使用 `message_id`。

### 历史消息回拉

接口 `GET /open-apis/im/v1/messages`（获取会话历史消息）支持按时间范围分页读取机器人
所在群的历史消息。权限：`im:message.history:readonly`（应用身份另需叠加
`im:message.group_msg`）。限制：分页每页 1~50 条、限频 1000 次/分钟、保密模式群不可读
（错误码 231203）、机器人必须在被查询的群中。入群前消息可读性受群设置「新成员可查看
历史消息」影响，属实测项（见「实测验收项」）。

### 依赖与权限清单

| 依赖/权限 | 用途 |
|---|---|
| `im:message.group_at_msg:readonly` | @ 消息接收（基础，二选一） |
| `im:message.group_msg` | 全量群消息接收（旁听） |
| `im:message.history:readonly` | 历史消息回拉 |
| `im:message:send_as_bot` | 机器人发送消息 |
| `im:chat:readonly` | 群信息读取（回拉时校验群名称） |

个人版飞书自建应用，企业管理员即创建者本人，权限申请无外部审批依赖。

## 核心决议

ADR-008 做出两组决议：通道层迁移（含钉钉处置），以及旁听上下文的设计四决策。

旁听上下文的采集链路总览：FeishuChannel 收全量消息后按是否 @ 分流——@ 消息走
ConsoleAgent 管线（照旧写入 `session.messages`），非 @ 消息写入旁听缓冲（不触发 LLM、
不回复）；上下文装配时两路渲染合并为一条时间线。四决策（形态、段 2 改造、历史检索、
历史回拉）均以该链路为前提展开。

### 通道层决议：飞书唯一通道与钉钉移除

1. **飞书为唯一协作入口通道**。新增 `FeishuChannel`，连接方式为 `lark-oapi` SDK WebSocket
   长连接，订阅 `im.message.receive_v1` 事件。
2. **移除钉钉通道代码**。删除 `channels/dingtalk.py`、`channels/dingtalk_parse.py`、
   `DINGTALK_*` 配置项、`main.py` 注册逻辑及通道级测试；ADR-001 标注「通道选型已被
   ADR-008 取代，机制借鉴清单仍有效」。git 历史保留完整回退路径。
3. **通道数据不迁移**。钉钉 `chat_id`（`cidV...`）与飞书 `chat_id`（`om_...`）属于不同
   体系，群绑定（GroupRepoBinding）、会话记录、测试数据均不迁移，飞书群重新绑定。个人
   项目数据量小，一次性成本可接受。
6. **钉钉死配置一并移除**：`DINGTALK_FREE_RESPONSE_CHATS` 在钉钉平台上等不到非 @ 推送，
   属死配置，随通道删除。

### 通道层决议：回复寻址与门控

4. **回复寻址机制变更**。钉钉经 session_webhook（5 分钟有效期）回复；飞书无此机制，改由
   bot 发消息 API（`tenant_access_token` 由 SDK 管理）按 `chat_id` 寻址回复。`ChannelAdapter.reply(chat_id, text)`
   接口不变，ConsoleAgent 层零改动；`UnifiedMessage.session_webhook` 字段在飞书通道恒为
   None，字段保留不删（字段语义为「来源通道自带的临时回复地址」）。
5. **门控配置语义沿用钉钉三开关**：`FEISHU_ALLOWED_CHATS`（群白名单）、
   `FEISHU_ALLOWED_USERS`（用户白名单）、`FEISHU_REQUIRE_MENTION`（默认 true）。
   @ 判定沿用 hermes 机制：判 mentions 列表中是否含机器人身份（open_id/user_id/name），
   `@_all` 视为 @。
6. **钉钉死配置一并移除**：`DINGTALK_FREE_RESPONSE_CHATS` 在钉钉平台上等不到非 @ 推送，
   属死配置，随通道删除。

### 旁听上下文四决策：形态与段 2 改造

1. **形态：原文，不做滚动摘要**。旁听内容以带说话人名的原文进入上下文。理由：旁听价值在
   保真细节（谁说了什么、以什么理由反驳），摘要必丢；个人项目规模下原文窗口 token 成本
   可接受；飞书历史 API 使缓冲可再生，无「错过即永久丢」压力。摘要层留待超大活跃群场景，
   本 ADR 不做。
2. **段 2 改造：渲染合并、存储分离**。`session.messages` 职责不变（仅管线内 @ 往来，继续
   喂滚动压缩与状态机）；新增 per-chat 旁听缓冲；`ContextAssembler._chat_section` 渲染时
   按 `ts` 时间戳将两者合并为单一 `[群聊上下文]` 时间线（`ChatMessage` 增加 `ts` 字段）。
   预算属性调整：合并段落中 @ 对话部分不可裁剪，旁听部分可裁剪（超预算先裁最老旁听）。

### 旁听上下文四决策：历史检索与历史回拉

3. **历史检索：存而不检索**。窗口外的旁听消息全量落 L2（SQLite，per-chat，含时间戳与
   保留上限），不建索引、不参与召回。理由：蒸馏结论的正道是记忆确认流→KBase；聊天记录
   作为检索语料质量差（碎片短句、语义依赖上下文）；待真实高频需求出现再评估。将来若启用
   检索，直接对存量数据补建 FTS5 索引即可。
4. **历史回拉：入群与重启双触发**。订阅 `im.chat.member.bot.added_v1` 触发入群回拉；重启
   时对 L2 消息表 `SELECT DISTINCT chat_id` 与 `group_repo_bindings` 中群做幂等补拉（靠
   message_id 去重）。回拉量：默认往前 7 天、最多 1000 条（先到为准），可配置。过滤：仅
   文本类消息，跳过 bot 自身消息。去向：时间窗内进旁听窗口，更老的落 L2 缓冲。

## 上下文段落模型（修订后）

修订后的段落模型共 5 段，段 2 由「仅 @ 往来」升级为「群内全量时间线」：

| # | 段落 | 预算属性 |
|---|---|---|
| 1 | `[会话状态]`（含本群可用仓库） | 不可裁剪 |
| 2 | `[群聊上下文]`（@ 往来 + 旁听消息合并时间线） | @ 部分不可裁剪，旁听部分可裁剪 |
| 3 | `[历史讨论摘要]`（Phase A 预留，恒为空段） | 可裁剪 |
| 4 | `<团队经验 KBase>` | 可裁剪 |
| 5 | `<正式文档 知识库>` | 可裁剪 |

回拉灌满后，`[群聊上下文]` 真正兑现「延续当前讨论」的口径——ADR-003 管线结构与
`ContextAssembler` 反向填充预算机制不变，仅段 2 数据来源与裁剪规则变更。

## 实测验收项

三项验收均依赖真实飞书环境，实现完成后逐项验证并回填结论：

1. **全量接收**：测试群非 @ 消息出现在旁听缓冲且不触发回复；@ 消息正常走管线且不重复
   入缓冲。
2. **回拉边界**：测试群先产生数日讨论，再将 bot 入群，实测「新成员可查看历史消息」开关
   对 `GET /im/v1/messages` 可读范围的影响，回填本 ADR。
3. **重启幂等**：重启后补拉不产生重复消息（message_id 去重生效）。

## 影响面

- `channels/`：新增 `feishu.py`、`feishu_parse.py`（结构沿用钉钉的「纯解析与 I/O 分离」
  布局）；删除钉钉两文件。
- `config.py`：新增 `FEISHU_*` 配置项与回拉参数（`FEISHU_BACKFILL_DAYS=7`、
  `FEISHU_BACKFILL_MAX=1000`）；删除 `DINGTALK_*` 全部配置项。
- `memory/types.py`：`ChatMessage` 增加 `ts` 字段。
- `console/context.py`：`_chat_section` 合并渲染 + 分部裁剪。
- `main.py`：通道注册替换。
- E2E：通道级用例改为飞书（事件归一化、去重、门控、回拉幂等）。
